2 · Namenskonventionen und Schlüssel

Damit auch große Datenbanken lesbar bleiben, gelten feste Regeln:

  • Kleinbuchstaben (SQL unterscheidet Groß-/Kleinschreibung bei Befehlen nicht), keine Umlaute, kein ß.
  • Tabellennamen in der Mehrzahl.
  • Jede Tabelle hat ein Präfix, das im ganzen Schema nur einmal vergeben wird. Alle Spalten der Tabelle tragen es: st_name, st_betten.
  • Fremdschlüssel: eigenes Präfix und Präfix der Quelltabelle: p_st_statnr.
  • id = alphanumerisch, nr = numerisch.
st_stationenPräfix st_, Mehrzahl
st_statnrPrimärschlüssel
p_patientenPräfix p_
p_st_statnrFremdschlüssel = p_ + st_ + statnr

Schlüsselarten

Primärschlüssel (PK)

Identifiziert eine Zeile eindeutig, nie NULL. VSA = Vollschlüsselattribut (ein Feld), TSA = Teilschlüsselattribut (der PK besteht aus mehreren Feldern).

Fremdschlüssel (FK)

Enthält Werte eines Primärschlüssels einer anderen (oder der gleichen) Tabelle. FSA = Fremdschlüsselattribut. Kann aus mehreren Spalten bestehen.

5 · Constraints: Regeln, die die Datenbank selbst überwacht

Constraints (Bedingungen) werden beim Einfügen, Ändern und Löschen geprüft. Verletzt eine Zeile die Regel, wird der ganze Befehl abgelehnt. Man kann sie direkt bei der Spalte schreiben (Spaltenconstraint) oder nach allen Spalten (Tabellenconstraint).

ConstraintRegelBeispiel
NOT NULLWert darf nicht fehlenst_name varchar(40) not null
PRIMARY KEYeindeutig und nicht NULLprimary key (m_p_patnr, m_lp_parameter)
UNIQUEWert kommt nur einmal vor (NULL darf öfter vorkommen)st_name … unique
FOREIGN KEYWert muss als Schlüssel in der Elterntabelle existierenforeign key (p_st_statnr) references st_stationen (st_statnr)
DEFAULTVorgabewert, wenn nichts angegeben wirdst_betten integer default 20

6 · FOREIGN KEY: ON DELETE und ON UPDATE

Was passiert mit den Patient*innen, wenn ihre Station gelöscht oder umnummeriert wird? Das legt der Fremdschlüssel mit ON DELETE / ON UPDATE fest:

NO ACTION

Standard. Es passiert nichts: Der Befehl wird abgelehnt, solange ein Fremdschlüssel auf die Zeile zeigt.

CASCADE

Die Änderung wird weitergegeben: Beim Löschen werden die abhängigen Zeilen mitgelöscht, beim Ändern wird der Fremdschlüssel mitgeändert.

SET NULL

Der Fremdschlüssel wird auf NULL gesetzt. Die Spalte darf dafür nicht NOT NULL sein.

Teste die Aktionen

7 · Tabellen ändern und löschen

Strukturen kann man auch nachträglich ändern:

-- Spalte hinzufügen / ändern / löschenalter table st_stationen add st_telefon varchar(20);alter table st_stationen modify st_telefon varchar(30);alter table st_stationen drop column st_telefon; -- Constraint nachträglichalter table p_patienten  add constraint fk_p_st foreign key (p_st_statnr)  references st_stationen (st_statnr); rename table st_stationen to st_abteilungen;drop table p_patienten;
Beim Nachrüsten werden die Daten geprüft

Legst du einen Fremdschlüssel erst nach dem Einfügen an, prüft die Datenbank alle vorhandenen Zeilen. Gibt es eine „verwaiste“ Zeile, wird der Constraint abgelehnt – erst die Daten reparieren.

Reihenfolge merken

Anlegen & Einfügen: erst Eltern, dann Kinder.
Löschen (DROP TABLE): erst Kinder, dann Eltern.

8 · Merksätze

DDL = Struktur
  • CREATE, ALTER, DROP
  • DML ändert Daten, DQL liest, DCL regelt Rechte.
CREATE TABLE
  • Name + Spalten in Klammern, durch Komma getrennt.
  • Jede Spalte: Name Datentyp [Constraints].
  • Befehl endet mit ;.
Constraints
  • NOT NULL · PRIMARY KEY · UNIQUE · FOREIGN KEY · DEFAULT · CHECK
  • Mehrspaltige Schlüssel: Tabellenconstraint.
Fremdschlüssel
  • Elterntabelle zuerst anlegen.
  • ON DELETE / ON UPDATE: NO ACTION, CASCADE, SET NULL.
